# DEEPSYQ — обязательное правило для Antigravity

Проект: `mvryhan-web/video-variator-android`. Основной сайт: `https://deepsyq.app`. Рабочая ветка платформы: `deepsyq-platform`.

## Перед любой правкой
1. Изучи `GEMINI.md` и актуальные D33/D34 в начале `AGENTS.md` и `DECISIONS.md`. При публикации — `docs/DEEPSYQ_CLOUDFLARE_ACCESS_RUNBOOK.md`.
2. Открой только нужную страницу, её прямые зависимости и текущий `git diff` / `git status`. Не начинай широкое переоформление или обход проекта.
3. Коротко назови точную задачу, разрешённые файлы, что останется без изменений, способ проверки. Если затронуть другой файл необходимо — объясни прежде, чем редактировать его.
4. Уже существующие пользовательские или чужие незакоммиченные изменения НЕ откатывай, НЕ перезаписывай и НЕ добавляй к своей задаче. Не изменяй другие ветки и не объединяй параллельные работы.

## Исполнение
- **ОДНО ПОРУЧЕНИЕ = МИНИМАЛЬНЫЙ DIFF.** Изменяй только явно названный элемент, его локальные стили и строго необходимые зависимости.
- Не переписывай целиком страницу/компонент, не рефактори, не меняй другие кнопки, layout, меню, переводы, тарифы, дизайн или backend «для улучшения».
- Сохраняй оригинальные изображения/видео, утверждённый визуальный стиль, действующие идентификаторы, обработчики, переходы, права и цены.
- Не создавай дублей JARVIX, Canvas, страниц, инструментов, маршрутов или новых вариантов одного и того же компонента.
- `pricing.html`, кошелёк, AI Credits, Stripe checkout/webhooks, Neon, авторизация, личные данные и их серверная логика защищены: не менять без отдельного прямого разрешения владельца.
- Не помещай секреты и ключи в исходники, сообщения, diff, логи или файлы правил.

## Обязательный контроль после изменения
1. Выполни `git diff --name-only` и `git diff --check`; покажи список затронутых файлов и короткую сводку diff.
2. Если затронуты неразрешённые файлы, исправь только **свои** лишние правки. Не удаляй чужие изменения.
3. Проверь нужный пользовательский сценарий и прилегающие действия, включая мобильную версию, если задача мобильная.
4. До `commit`, `push`, `merge` или `deploy` предъяви diff владельцу для проверки, если включён режим Review. Не маскируй массовые изменения под один коммит.

## Выпуск в Cloudflare
- Production: `https://deepsyq.app`; резервный TEST: `https://test.deepsyq.pages.dev`; `deepsyq.pages.dev` — тоже production.
- Публикуй только согласованный набор изменений, сравнив его с текущим LIVE baseline, а не со старым локальным репозиторием.
- **Никогда** не запускай статический Pages deploy, который удаляет действующий Worker/Functions. Требуются доказанное сохранение Worker, bindings, API, авторизации, Stripe и данных, плюс доступный откат.
- Если это не доказано: `BLOCKED_MAIN — NOT PUBLISHED`; ничего не перезаписывай и не утверждай, что публикация выполнена.
- После успешной публикации проверь конкретную страницу на production и сообщи точный diff, commit/deployment и результат. Правки в GitHub сами по себе НЕ означают публикацию.

Эти инструкции ограничивают действия Antigravity; утверждённые в репозитории правила владельца имеют силу. Если возникло противоречие, останови изменение и сообщи о нём до продолжения.
