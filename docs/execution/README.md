## Обязательное исполнение каждым агентом

1. **Read first once:** `AGENTS.md`, `PROJECT_STATUS.md`, исходный BASE TXT/этот canonical TXT и конкретный checklist; прочитать свежие PR и активное владение. Не повторять полный аудит при каждом коммите.
2. **Одна зона ответственности:** указать Block/BASE, ветку, PR и следующий непроверенный этап; не начинать чужие задачи и не менять утверждённый Home.
3. **Порядок без хаоса:** закончить один этап, подтвердить критерий тестом/фактом, записать статус и переходить к следующему. Уже готовое *подтвердить с существующим доказательством*, а не переписывать.
4. **Blocker отдельно:** если нужны ключ, платёжное согласие, оплачиваемый API, backup/upgrade DB, owner-approved визуальный материал или готовность Block 2 для Block 6, отметить `BLOCKED` + причину + разрешённое действие. Не делать вид, будто шаг выполнен; можно выполнять только документированную независимую, безопасную работу своего блока.
5. **Никаких вечных проверок:** один быстрый контроль перед пакетом работ, затем targeted tests. Полный CI только перед merge/release или при доказанной необходимости. Не пересоздавать готовые тесты.
6. **Результат каждого шага:** что изменено, точная ссылка на PR/commit, тест и статус; где нет подтверждения — `PARTIAL`/ `BLOCKED`, не ✅.
7. **Чёткие границы:** BASE + Blocks 1–7 в `main` после зависимостей, code review, CI и safety gates; Render auto-deploy main, поэтому backup/recovery/Stripe/paid providers проверяются ДО функционального merge.
8. **Финал работы:** сохранить короткую сводку в `PROJECT_STATUS.md`; перечислить completed/remaining/next single action, а не пересказывать весь проект. Для следующего агента чек-лист — место продолжения.
