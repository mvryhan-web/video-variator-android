DEEPSYQ — CANONICAL ROADMAP BLOCKS 1–7

IMPORTANT
- These are the seven canonical Deepsyq roadmap blocks.
- BASE / the original large production/site TXT is separate and is NOT Block 1.
- Preserve this numbering.
- Do not rebuild the project from scratch.
- Reuse the existing production architecture, auth, PostgreSQL, Stripe, jobs, credits/wallet, providers, Video Uniquifier, Everyday Tools, and current Studio wherever possible.
- Do not create duplicate billing, auth, database, router, provider, or project systems.
- No fake integrations, fake models, fake responses, or fake “done” states.
- API keys and secrets are server-side only.
- Paid/expensive AI operations must account for usage, credits, provider cost, limits, idempotency, and failure handling.

============================================================
BLOCK 1 — MULTI-AI COMPARE + SMART MODEL ROUTING
============================================================

GOAL
On the main Deepsyq AI screen, next to Smart, add Compare AI.

MULTI-AI COMPARE
One user prompt should run parallel real API requests to multiple connected/enabled AI models/providers.

Baseline providers:
- OpenAI
- Google Gemini
- Anthropic Claude
- Mistral AI
- optional hidden future provider slot
- BytePlus ModelArk may be added as another provider when appropriate and verified

UX
- User enters one prompt.
- Selects Compare AI.
- Deepsyq sends the prompt to 2–4 enabled models.
- Show separate answers for each model/provider.
- User can Copy, Save, Continue, reuse an answer, and press “Combine into one best answer”.
- “Combine into one best answer” must be a real synthesis step and its extra AI cost must be accounted for.

SMART MODEL ROUTING
Smart chooses the model based on:
- task type and capability
- measured historical quality
- reliability
- latency
- provider availability
- cost
- user plan
- available AI credits
- model requirements/limits
- context/modalities

Do NOT:
- assume one provider is always best
- hardcode stale model versions
- silently route to a much more expensive model without policy
- retry an ambiguous paid provider call automatically

Technical requirements:
- config-driven providers/model IDs
- server-side secrets
- async parallel execution
- timeout/fallback/partial-failure handling
- tokens/usage tracking
- actual provider cost
- credits/plan limits
- latency/success/failure metrics
- routing-decision reason
- no fake results

Trial:
- $0.99 trial gets limited Compare/Smart usage
- no unlimited AI

BytePlus:
- may be one provider in the shared router
- must not replace the whole Deepsyq architecture

BLOCK 7 — PRICING, CREDITS, STRIPE & UNIT ECONOMICS
============================================================

GOAL
Build the commercial Deepsyq system where users pay through the existing Stripe, receive AI credits/entitlements, use AI, and Deepsyq controls real cost and gross margin.

Important:
- reuse existing Stripe
- reuse existing Checkout
- reuse existing Products/Prices where already present
- reuse existing webhooks
- reuse PostgreSQL
- reuse users
- reuse current AI wallet/ledger foundations
- do NOT create a second billing stack
- do NOT duplicate existing plans/Price IDs/backend logic
- do NOT invent provider prices

EXISTING DEEPSYQ PLAN BASE
- Basic — $9
- Pro — $24
- Business — $99
- Lifetime — €2,999

Lifetime:
- separate product
- for Everyday Tools / legacy Free Tools + Video Uniquifier according to approved policy
- NOT unlimited paid AI
- NOT lifetime access to every future provider call

TRIAL

Trial — $0.99

Do not finalize/enable it until approved:
- duration
- included AI credits
- included features
- renewal/non-renewal

- CTA

AI CREDIT SYSTEM
Need:
- AI wallet
- auditable ledger
- purchase
- reserve
- capture
- release
- refund
- debt/reconciliation primitives
- idempotency

Before expensive generation:
quote
→ verify balance
→ reserve atomically
→ start provider job
→ finish provider job
→ capture approved/actual credits
→ release unused reservation or confirmed failure

Never:
- start expensive work before checking/reserving credits
- automatically refund an ambiguous provider call when provider acceptance is unknown
- automatically retry ambiguous paid generation

STRIPE
All user payments go through the existing Stripe.

Use Stripe for:
- subscriptions
- approved Trial
- one-time AI credit packs
- existing plan checkout
- customer mapping

User pays Deepsyq through Stripe.
Deepsyq separately pays AI providers from business/provider accounts.
A customer’s Stripe payment does not directly “pay the provider per user”.

Credit grants:
- only after verified Stripe webhook
- idempotent
- record webhook event
- duplicate webhook must not duplicate credits

Monthly credits:
- grant after confirmed billing event
- server-side renewal logic

ONE-TIME CREDIT PACKS
Support Buy Credits.

Benchmark sizes:
- 1,000
- 10,000
- 100,000
- 1,000,000
- 10,000,000

Real prices must be derived from unit economics.
Discounts are allowed only while maintaining safe margin.

UNIT ECONOMICS
For each AI call record:
- provider
- model
- task type
- tokens / seconds / images / video duration / audio duration as relevant
- provider list price
- actual provider cost
- internal Deepsyq credit cost
- charged credits
- reserved credits
- markup
- allocated Stripe fees where applicable
- infrastructure allocation where applicable
- retry/failure cost
- final margin

Formula:
provider cost
+ infrastructure
+ Stripe fees
+ expected failure/retry risk
+ safety margin
= minimum sustainable price

Then:
minimum sustainable price
→ Deepsyq credits
→ plan allowance / credit-pack pricing

Do not finalize Deepsyq pricing until real provider prices are verified.

MODEL-SPECIFIC CREDIT COST
Different models may cost different credits.

Pricing must be:
- model-specific
- capability-aware
- duration/size-aware where relevant
- server-side
- config-driven

Do not hardcode stale provider prices in the frontend.

PRICING ENGINE
Server-side pricing engine:
- input provider/model/task
- read verified provider economics
- apply approved markup
- return AI credit quote
- save estimate
- save actual cost after job
- compare estimated vs actual

Frontend receives only safe quote data.
No provider billing secrets exposed.

ADMIN ECONOMICS
Owner/admin should see:
- AI revenue
- confirmed credit purchases
- subscriptions
- provider cost
- infrastructure cost where available
- credits sold
- credits used
- credits held
- refunds/releases
- average cost per user
- average cost per generation
- most expensive models
- highest-failure models
- margin by provider
- margin by model
- margin by plan
- gross margin
- abnormal spend

If currencies differ:
- do not sum them into one fake revenue total without an FX/accounting policy

PRICING SAFETY
Never:
- include unlimited paid AI in Lifetime
- grant credits before confirmed webhook
- create duplicate Stripe Products/Prices
- invent provider pricing
- present a plan as live when Price ID/webhook is not configured
- auto-change public pricing without owner approval
- silently switch an expensive job to a much more expensive fallback model without approved routing policy

EVERYDAY TOOLS
- may have free/limited first use
- then upgrade/plan/limits
- do not confuse cheap/local tools with expensive paid AI provider operations
