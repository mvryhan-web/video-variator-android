# OWNER EXECUTION DECISION — A/B/C/D SELF-VERIFY + SELF-MERGE (2026-10-20)

**ИЗМЕНЕНО РЕШЕНИЕМ ВЛАДЕЛЬЦА, 2026-10-20, см. [DECISIONS.md](../DECISIONS.md), D16.**

**ОБЯЗАТЕЛЬНО:** агенты **A, B, C и D** независимо и полностью ведут каждый свой закреплённый участок: читают актуальный SHA/claims, разрабатывают, проверяют результат, исправляют провалившиеся проверки, запускают разрешённые бесплатные тесты/CI, проверяют конфликт файлов и **САМИ объединяют свой готовый PR в `deepsyq-platform`**. Координатор №5 **НЕ является обязательным reviewer/approver/merger** и не может быть причиной остановки безопасной DEV-интеграции. **Не направлять ему PR на обязательную проверку или разрешение; не ждать его ответа.**

**После объединения:** каждый агент подтверждает реальный DEV merge SHA, проверяет итоговые DEV-регрессии и, для уже авторизованного отдельного безопасного read-only preview, сам выполняет доступную ему безопасную публикацию и проверяет фактический LIVE deploy SHA, если есть разрешённый доступ. **DEV merge не равен production/live commerce.** GitHub CHECKPOINT в своей issue/claim/status содержит PR, SHA, CI, diff, merge SHA, preview link или чёткую блокировку. Уведомление общего журнала — только асинхронная информация, **не просьба о проверке**.

**Точные предохранители остаются обязательными:**
- До self-merge: все требуемые тесты на **финальном SHA** завершились успешно; финальный diff строго своей зоны, без коллизии с открытым PR, без force-merge; нет скрытых неудачных CI или неподтверждённых оценок.
- При совпадении с чужим файлом/тестом: адресное согласование точных hunks **между ответственными агентами**, затем повторная проверка финального SHA; **не ждать решения координатора**, не стирать и не переписывать чужой код.
- **B/D финансовая и приватная граница:** обязательная взаимная независимая peer-проверка безопасности (в частности PR174 + строгие D306 tests) производится **непосредственно B и D**; B самостоятельно объединяет PR174 в DEV только после точного D PASS и зелёных тестов. Отрицательный D BLOCKED запрещает merge, пока не исправлен. D для собственных финансовых изменений выполняет соответствующую независимую проверку/негативные тесты. **Peer gate не заменяется самопроверкой автора**, но #5 не является gate.
- Защищённые оригинальные Home/героиня/шесть видео и шесть исторических заголовков/подписей не меняются без нового прямого согласия владельца; не повторять DONE.
- **`main`/production, реальные Stripe/платные AI и потенциально платные вызовы, опасные миграции/клиентские данные** не авторизованы данным решением: только соответствующее прямое разрешение владельца и безопасность/release gate D. Никаких обходов branch protection/обязательных GitHub checks.
- Если GitHub права/branch rules запрещают self-merge, фиксировать точный внешний `MERGE_PERMISSION_BLOCKED`; не объявлять выполненным и не просить #5 «ревью» как рабочий этап. Владельцу сообщается только реальная необходимость изменить права/защиту.
- **Jules:** эта D16 поправка относится именно к A–D; условия активации Jules и отдельная изоляция опасных default-main PR остаются действующими до отдельного решения владельца.

**Цикл каждого A–D:** `код → актуальный CI → peer security только при применимости → собственный DEV MERGE → проверка merged HEAD → разрешённая публикация preview → CHECKPOINT → следующий свой BASE шаг`. Реальные проверки и безопасные блокировки важнее скорости. Старые тексты «only coordinator #5 merges DEV», «A–D stop at READY_TO_MERGE» и «send PR to #5 for approval» являются **историческими и недействующими** после этого прямого решения владельца. Оригинальные BASE 55/Blocks 1–8 и 4 несменяемых приоритета не меняются.
