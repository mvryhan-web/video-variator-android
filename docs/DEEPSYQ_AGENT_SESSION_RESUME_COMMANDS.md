## Обязательный режим работы: НЕ ОСТАНАВЛИВАТЬСЯ ПОСЛЕ ПРОМЕЖУТОЧНОГО ШАГА

1. **Внутри активной сессии** после любого удачного теста, коммита, PR, исправления или отчёта **немедленно выполнять следующий необходимый шаг ЭТОГО ЖЕ пункта**, пока весь оригинальный пункт реально не DONE, либо не наступит технический лимит сессии, либо не останется исключительно подтверждённый внешний блокер/требуемое разрешение. Не заканчивать ответ словами «жду OK GO», «что дальше?» или «продолжу позже», когда доступная разрешённая работа ещё есть.
2. **Максимально использовать доступную сессию**, а не останавливаться после одной операции или выбранного произвольного числа коммитов. Если техническая платформа вынужденно закончила ответ, сессию или отозвала инструмент, она **не может работать дальше сама по себе**. Записать прогресс и конкретный следующий шаг в GitHub, не придумывать фоновую работу и не обещать автоматического продолжения без следующего сообщения пользователя.
3. **Смена окна — не смена работы.** Когда чат достиг лимита, сохранить CHECKPOINT/HANDOFF до лимита по возможности: роль, один текущий BASE №, полные критерии DONE и оставшиеся подпункты, Issue, ветка/PR, последние SHA/CI, конфликтные файлы и единственное следующее действие. Указать owner-у короткую команду для нового чата. В новом чате подтвердить точную роль и прежний пункт по GitHub и продолжить существующую ветку/PR **с последней незавершённой операции**. Не начинать заново, не переписывать готовое и не перепрыгивать на другую роль/пункт.
4. **DONE означает полностью проверенное оригинальное требование**, включая необходимые проверки, актуальный SHA, интеграцию и применимый пользовательский сценарий; не путать локальный тест, маленький PR и release/production. При реальном внешнем ограничении завершить всё доступное, назвать конкретную зависимость и обратиться к №5 за документированным разрешением на смену пункта. Нельзя включать платные AI, Stripe, secrets, production или оплачиваемые тесты без согласования.
5. Координатор №5 **не останавливается после одной проверки**: продолжает последовательно устранять коллизии, проверять критерии пунктов, помогать закрывать действительно маленькие незанятые пробелы только после проверки границ A–D, улучшать интеграцию и документировать блокеры. Как и для других, технический лимит требует CHECKPOINT и продолжения в новом чате, а не объявления проекта DONE.
