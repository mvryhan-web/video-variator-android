## Three distinct delivery gates
1. **Visual/no-spend preview (already exists):** demonstrate the approved design, responsive navigation, real licensed media when available, no paid API calls, no claims that checkout/generation works. Refresh only with QA and owner-approved Home asset fidelity. Keep `noindex` so preview pages do not compete with future public SEO.
2. **Isolated commercial staging (NOT YET VERIFIED):** separate service/config from production, production data not copied without permission, separate safe/test database and object-storage bucket with isolation/cleanup, staged migrations and restoration proof; use Stripe **test mode** and signed test webhooks, approved low-risk provider smoke testing under budget with valid credentials/terms, signed result URL download, History persistence, cancelled/failed job credit release, cross-user access denial, mobile/old Tools checks. Do not treat mock browser tests as this live-service acceptance. Carefully preserve API, DB, Stripe and object-store access restrictions.
3. **Public paid launch (NO-GO today):** all relevant BASE #51 and #54 acceptance criteria, launch-readiness gates, approved real provider pricing/credit margins, production backup+restore and migrations, Webhook/refund/idempotency, timeouts, safeguards, CI/mobile release QA, SEO checks and explicit owner go/no-go approval are met. Only then consider moving new Home/paid flags to public site. Existing subscriptions and legacy tools must continue unchanged.
