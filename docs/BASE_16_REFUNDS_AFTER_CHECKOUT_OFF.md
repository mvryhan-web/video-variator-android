# BASE #16 — historical AI refunds must survive Checkout shutdown

Stripe credit pack Checkout is intentionally disabled by default and must remain controllable with `AI_BILLING_ENABLED=false`. A newly discovered failure path: a **signed** `charge.refunded` event for an already-paid AI wallet charge with the positive `aiWallet:'v1'` marker was rejected as `AI_BILLING_WEBHOOK_DISABLED` whenever operators disabled new checkout. That rejection could outlast webhook retries and leave already-revoked cash as spendable wallet credits.

The isolated correction allows positively AI-marked, **same-mode** historical refunds to reach the **existing** cumulative, idempotent `GenerationWallet.refund` reversal even with checkout OFF. It does not enable Checkout, invoices, new credit grants, price plans, public generation or providers. Unmarked unrelated legacy refunds still return false without querying the AI wallet when both AI credit programs are disabled; cross-mode positive AI refunds still fail. Positively tagged refunds without a recorded purchase remain retriable (existing `AI_REFUND_PURCHASE_PENDING`) rather than silently acknowledged.

Coverage: dedicated shared-refunds unit extends tests for a durable pending purchase, tagged historical reversal delegation, legacy isolation and cross-mode strictness; existing checkout/wallet/refund unit suites run via pre-existing `base16-legacy-refunds.yml`. No new CI workflow or external API call. For unmarked historical Stripe charge events, ambiguity remains: explicit AI marker is required while both AI payment programs are disabled to avoid accidentally interrogating or interfering with pre-existing non-AI subscriptions. Complete staging test-mode refund, historical unmapped-event reconciliation, production DB restore and live owner sign-off remain separate blockers. Original BASE #16 PARTIAL/NOT LIVE.
## Explicit AI Stripe billing mode guard

The existing runtime had treated every unknown/missing `AI_BILLING_MODE` as `test` and could activate test Checkout if `AI_BILLING_ENABLED=true` and a test Stripe key was present. This follow-up requires an **explicit** mode of exactly `test` or `live` before the Stripe key can match for AI billing activation. Existing declared test/live modes behave exactly as before. Configuration responses remain backward-compatible but report `enabled:false` until corrected. This prevents unintended test Checkout during a misconfigured release; it does not change prices, Stripe sessions, webhook signatures or customer credits.

The existing generation-billing unit suite adds exact-mode checks and an Express HTTP-level fail-closed Checkout test proving zero DB/Stripe calls. Historical refund processing remains governed separately by the signed-event, mode and positive AI marker checks above.

## Late paid Checkout webhooks after new sales are disabled

A previously created Stripe Checkout can be paid just as an operator disables new AI credit sales. Both `checkout.session.completed` and `checkout.session.async_payment_succeeded` had been rejected immediately by `AI_BILLING_WEBHOOK_DISABLED`, stranding a valid payment without credits. The webhook handler now permits **reconciliation of a saved prior order** while `AI_BILLING_ENABLED` is OFF **only if** the current Stripe key matches the explicit test/live mode, the wallet database and signing configuration exist, and a Stripe session retrieval method is available. This is a server-side response to an event that has **already passed the shared Stripe signature verification**; it cannot create a Checkout. An absent order, foreign session/user, changed amount/currency/Price ID, wrong payment mode, or foreign event mode still fails closed. The existing idempotent wallet purchase ledger is the sole grant path.

This guard does not enable a new Checkout URL, public generation, subscriptions, trial allowance, or provider dispatch. It does not assert production Stripe webhooks were delivered or that an old payment without a persisted order is recovered. Owner-approved staging with a signed payment/refund pair is still required.
