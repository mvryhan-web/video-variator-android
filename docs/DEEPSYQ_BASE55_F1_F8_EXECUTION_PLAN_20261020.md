## 4. Порядок реализации: Волны 0–4

### Волна 0 — сохранность, правда, доверие и release-подготовка

- Сначала инвентаризировать **свежую** ветку, действующие auth/PostgreSQL/Stripe/router/jobs/storage и PR; не объявлять отсутствие по упрощённому preview.
- Сохранить утверждённый Home и пользовательские медиа, не менять шесть роликов/исходные заголовки и визуальную систему на внутренних страницах без утверждения.
- Проверить приватность аккаунтов, разграничение данных, регрессии Video Uniquifier и Everyday Tools, безопасность тестового стенда; подготовить резервирование, проверку обратной совместимости и откат.
- Проверить владельческие права и достоверность видео/изображений Inspiration, без копирования Lumina/DeepSeek.
- SEO release plan: инвентаризация публичных адресов, canonical/robots/sitemap/schema.org, title/description/alt, серверной видимости, скорости/mobile; подготовка без преждевременного индексирования preview.
- User trust: правдивые Terms / Refund / Contact / Privacy, ясно отличимые коммерческие условия; не публиковать неутверждённые юридические обещания.
- Приёмка: рабочее старое приложение не сломано, noindex preview сохранён, известны реальные внешние блокировки, есть план отката.

### Волна 1 — проверенная коммерческая цепочка BASE §51 и F7

Сохраняем минимум существующей Home/Canvas/Studio/History и их навигацию; не перестраиваем их ради новой схемы.

**Обязательный путь E2E:** пользователь/вход → выбранная доступная Image/Video-модель → **серверная цена в AI-кредитах до подтверждения** → проверенная покупка Stripe (только в test mode на этапе бесплатной проверки) → webhook с подписью и однократным начислением → атомарный резерв/идемпотентность → backend Provider Router/адаптер → реальное Image и реальное Video при подтверждённом бесплатном способе тестирования → долговременное собственное приватное хранилище → итоговое списание/разблокировка остатка/обработка неизвестного состояния → owned History и Download → owner-only затраты и маржа.

**Безусловные требования:** API/БД только user-scoped; защита от двойного запуска/двойных webhook/таймаутов; никакого провайдера из браузера; без внешних временных media URL; фоновые job переживают перезапуск; безопасный retry; корректные capability limits; provider costs не открываются клиенту. Если бесплатный реальный AI smoke test недоступен, **BLOCKED**, не симулировать LIVE_VERIFIED и не тратить деньги.

**Порядок внутри Волны 1 по зависимостям (проверить уже готовое, реализовать только GAP):**
1. Проверенная auth/account identity + PostgreSQL и схема owned generation jobs/миграции.
2. Server-only AI Router + активный адаптер/модели + capabilities, безопасный async processing.
3. Storage и private signed access, восстановление задач/status/download.
4. F7: существующий кошелёк/ledger, серверный прайсинг, atomic reserve/settle/refunds.
5. Stripe test Checkout + signed webhook, подтверждённые кредиты; реальный Trial только после отдельно утверждённых условий.
6. Image Studio, Video Studio, Canvas и базовый History/My Creations: доказать всю цепочку и повторные входы.
7. Безопасная финансовая/приватная приёмка B↔D, mobile/Desktop регрессии, административные экономики и стоимости.

**Условие готовности Волны 1:** пройдены все пункты BASE §§51/54 с доказательствами конкретных запусков, результатов, статусов, собственных ссылок и корректной платёжной схемы. Stripe test-mode и mock CI — только тестовые доказательства, **не** живые продажи. Real commercial release отдельно требует approval, LIVE env, реальный провайдер и production verification.

### Параллельный поток к Волне 1 — SEO, конверсия, качество и F5 Lite

Разрешённые бесплатные задачи могут вестись одновременно без вмешательства в чужие claimed-файлы: SEO-инвентарь и release-only indexing план; copy/CTA, мобильные переходы, пользовательский путь и страницы доверия; rights-gated Inspirations; минимальный owner-only F5 Lite (read-only мониторинг uptime/Stripe failures/spend anomaly + email при отдельном разрешении на инфраструктурную активацию). Даже при быстром развитии F2/F4/F6 не включать платные возможности без подтверждённых credits.

**Критерии UX конверсии:** пользователь понимает что получит, сколько кредитов будет удержано, когда списание финально, что происходит при ошибке и как позже скачать результат; проверка mobile и desktop. Аналитика не должна раскрывать чужие или чувствительные prompts.

### Волна 2 — удобная рабочая платформа

- **F4**: расширенные Recent/Drafts/Completed/Favorites, Open/Rename/Duplicate/Archive/Delete (с подтверждением), templates/Agent Skills links; поверх единого существующего jobs/workspace, **не** второй базы.

- BASE AI Apps и богатый Canvas/Studio в дополнение к минимальному коммерческому пути; функции, реально зависящие от F2, показывать честно disabled/coming soon.

### Волна 3 — продуктовый рост

- **F2**: один-два заранее определённых workflow (например, Etsy-listing или promo/video) → видимый план → quote → согласие → async jobs → owned output; автономный универсальный оркестратор только после LIVE_VERIFIED BASE §51.

- Масштабирование моделей, onboarding, SEO-контента, метрик конверсий/маржи и дополнительных утверждённых сценариев без обхода финансовых и лицензионных требований.

### Волна 4 — дополнительные большие функции

- **F6 Voice**: полнофункциональный опциональный голосовой помощник с явным включением микрофона, Stop/Mute/End и оригинальным голосом, с проверкой устройства/браузера. Готовые изолированные бесплатные компоненты Jules можно разрабатывать раньше, **не включая** платный AI Voice и не дублируя задачи.
