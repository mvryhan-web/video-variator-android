# JARVIX NEW — подготовка платных AI-моделей и фирменного голоса

**Статус на 12.11.2026: подготовлено в TEST, по умолчанию выключено. Нет реальных вызовов или списаний.**  
Ветка `jarvis-new`, тест: https://jarvis-new.deepsyq.pages.dev/. Рабочий DEEPSYQ и старый JARVIX не меняются.

## Что реализовано

- Серверный шлюз: `scripts/jarvix_new_paid_gateway.js` с маршрутами:
  - `GET /api/jarvix-new/paid/status` — безопасно сообщает, включён ли платный режим.
  - `GET /api/jarvix-new/paid/access` — проверяет авторизованного пользователя через **доверенный сервер**, а не localStorage/план из браузера.
  - `POST /api/jarvix-new/paid/turn` — проверка подписки, резервирование стоимости, вызов модели, озвучка владельческим голосом, подтверждение списания.
- Доступны только активные тарифы `basic`, `pro`, `business`. Пробный план и бесплатный пользователь не получают дорогую AI-генерацию. Кредиты сами по себе не заменяют проверку тарифа.
- Для каждой подписки выбирается своя модель **на сервере**. Пользователь не может заменить модель, тариф или лимит в браузере.
- Шлюз требует **голосовой сервис с подтверждённым профилем JARVIX**. Если нужного голоса нет, произвольный системный голос не подставляется.
- Все внешние ключи — только секреты Cloudflare, не в клиентском JavaScript и не в GitHub.
- Без успешно подтверждённой подписки и резервирования бюджета вызов платной AI-модели запрещён.
- Реальные операции `reserve/capture/release` должны быть атомарными, долговечными и идемпотентными на стороне будущего биллинг-сервиса. При неизвестном результате `capture` запрещён слепой `release`.
- Тестовый JS `app/src/main/assets/jarvix-new-voice.js` использует новый маршрут только при разрешении сервера, иначе сохраняет текущий режим записанных MP3 и Ollama.
- Все остальные API в тестовом Cloudflare Pages по-прежнему блокируются.

## Что нужно будет подключить ПОЗЖЕ, когда владелец разрешит

В настройках **Cloudflare Pages → deepsyq → Settings → Variables and Secrets → Preview** задать привязки (НЕ В PRODUCTION). Заполнять только после проверки тестовой конфигурации:

| Переменная | Назначение |
|---|---|
| `JARVIX_PAID_ENABLED` | Переключатель. Пока **`false`**. При `true` **и полной конфигурации** разрешает новый маршрут |
| `JARVIX_MODEL_CHAT_URL` | HTTPS URL совместимого `chat/completions` API модели |
| `JARVIX_MODEL_API_KEY` | Секретный ключ выбранного AI-провайдера |
| `JARVIX_MODEL_BASIC` | Разрешённая модель для Basic |
| `JARVIX_MODEL_PRO` | Разрешённая модель для Pro |
| `JARVIX_MODEL_BUSINESS` | Разрешённая модель для Business |
| `JARVIX_ENTITLEMENT_VERIFY_URL` | HTTPS endpoint сервера проверки реальной сессии и активной подписки |
| `JARVIX_ENTITLEMENT_SERVICE_KEY` | Секрет межсерверной проверки |
| `JARVIX_BILLING_RESERVATION_URL` | HTTPS endpoint атомарного резерва/захвата/отпуска средств |
| `JARVIX_BILLING_SERVICE_KEY` | Секрет биллинг-сервиса |
| `JARVIX_OWNER_VOICE_RENDER_URL` | HTTPS endpoint будущего синтеза оригинальным голосом JARVIX |
| `JARVIX_OWNER_VOICE_API_KEY` | Секрет голосового сервиса |
| `JARVIX_OWNER_VOICE_ID` | Идентификатор одобренного владельцем голоса; например `jarvix-owner-v3` |
| `JARVIX_MAX_RESERVATION_CENTS` | Положительный максимальный бюджет на один запрос, устанавливается владельцем после сверки себестоимости |
| `JARVIX_MAX_OUTPUT_TOKENS` | Ограничение длины ответа, поддерживается 16–512 |

**ВАЖНО:** установка `JARVIX_PAID_ENABLED=true` сама по себе не создаёт AI-провайдера, не включает Stripe, не создаёт подписку и не генерирует голос. Должны реально существовать три серверные интеграции (проверка права, денежные резервы, голосовой рендер) и API-модель, и они должны пройти end-to-end тест с подтверждённой подпиской на TEST.

### Контракт сервера проверки подписки

`POST JARVIX_ENTITLEMENT_VERIFY_URL` с `Authorization: Bearer <service key>`, `X-Jarvix-User-Session: <user session token>`, JSON `{"purpose":"jarvix-new-paid-access"}`. Только сервер доверенного пользователя, читая настоящую биллинговую БД/Stripe, отвечает:

```json
{"verified":true,"active":true,"subjectId":"user-4321","plan":"pro"}
```

Если статус не подтверждён, HTTP-ошибка, trial, free, отменённая подписка и т.п. — доступ отклоняется.

### Контракт биллинга

`POST JARVIX_BILLING_RESERVATION_URL` через сервисный ключ. Тело содержит `action`, `requestId`, `subjectId`, `plan`, `maxReservationCents`, `purpose`, при повторных действиях — `reservationId`. Возможные `action`:

- `reserve`: ответ `{"allowed":true,"reservationId":"reserve_abcdef1234"}`; сервис обязан проверить фактический баланс/план и атомарно резервировать бюджет, не из памяти Edge Worker.
- `capture`: `{"ok":true}` только после долговечного подтверждения фактического списания с идемпотентным requestId.
- `release`: `{"ok":true}` после отмены резерва, если генерация не завершена.

Обязательно реализовать воспроизводимую сверку неизвестного результата `capture`, защиту от повторного запроса и журнал затрат. Нынешний шлюз не может гарантировать верхнюю границу стоимости непроверенного поставщика; расчёт тарифов и provider usage нужно проверить отдельно.

### Контракт голосового сервиса

`POST JARVIX_OWNER_VOICE_RENDER_URL` с сервисным ключом:

```json
{"text":"Привет, я JARVIX.","language":"ru","voiceId":"jarvix-owner-v3","format":"mp3","sampleRate":48000}
```

Ответ: `Content-Type: audio/mpeg`, `X-Jarvix-Voice-Id: jarvix-owner-v3` и реальные MP3-байты. Требуется корректная работа RU, EN, FR, ES именно **нашим одобренным голосом**, предварительное прослушивание и проверка лицензии модели. Одного HTTP-заголовка недостаточно для подтверждения схожести звучания: это отдельный приёмочный тест.

Шлюз не включает платный браузерный TTS, не подменяет голос системным, возвращает ошибку при отсутствии одобренного голосового движка.

## Проверка

Автоматические тесты `tests/jarvix_new_paid_gateway.test.mjs` полностью симулируют ответы модели, подписки, биллинга и голоса — **никакого платного запроса, Stripe и внешней генерации**. Они проверяют: OFF, отсутствие конфигурации, запрет trial/free, запрет подмены тарифа, лимиты бюджета, отказ поставщика, неподходящий голос, отсутствие двойного release после неопределённого capture, правильное сохранение бесплатного маршрута.

Рабочий сайт нельзя менять без нового отдельного разрешения владельца.
